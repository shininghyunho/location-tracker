# ADR-010: 장소 이름 추천 = 카카오 로컬 API + 클라이언트 자체 쿼터

- **상태**: 확정 (2026-07-25)
- **결정**: 라벨 시트의 주변 상호 추천은 카카오 로컬 카테고리 검색(반경 100m, 카테고리 4종 = 탭 1회 4콜 고정, 버튼 탭 시에만 호출)으로 한다. 서버 없이 클라이언트가 localStorage 쿼터로 일 500콜(콘솔 무료 쿼터와 동일)을 선차단하고, 429/401을 받은 날은 당일 잠근다. REST 키는 `.env`(`VITE_KAKAO_REST_KEY`)로만 주입한다.
- **대가**: 키가 APK 번들에 포함된다 — 개인 앱 + 무과금 키라 유출 피해가 쿼터 소진뿐이라 수용. 쿼터가 기기별 카운트라 여러 기기면 합산이 안 된다(1인 1기기 수용). 키 없음·오프라인에선 추천 칩이 조용히 빠진다.

## 배경

체류에 라벨을 붙일 때마다 상호를 직접 타이핑하는 마찰이 컸다. 좌표는 이미 있으니 주변 상호를 칩으로 제안하면 탭 1회로 끝난다. 이 프로젝트 최초의 외부 API 의존이라, 무엇을 쓰고 쿼터를 어떻게 지킬지가 결정 지점이었다.

## 검토한 대안

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **카카오 로컬 (채택)** | 국내 POI 데이터 최강. 카드 등록 없는 무료 일 500콜. 좌표+반경 카테고리 검색 지원 | 쿼터 500이 작다 | 버튼 탭 시에만 4콜이라 500이면 충분 |
| 네이버 지역검색 | 쿼터 큼(일 25,000) | 좌표+반경 검색 미지원(키워드 쿼리 기반) — "이 좌표 주변 상호" 용도에 부적합 | 용도 불일치 |
| Google Places Nearby | 글로벌 커버리지 | 결제 카드 등록 필수, 국내 POI 열세 | 개인 무과금 원칙 위배 |
| OSM Overpass | 완전 무료·무키 | 국내 상호 데이터가 빈약 | 추천 품질 미달 |

## 지켜야 할 것

- **탭 1회 = 4콜 불변** — 카테고리 코드를 추가하면 상한 계산이 깨진다. 늘릴 땐 `DAILY_CALL_LIMIT` 여유를 재검토.
- **`DAILY_CALL_LIMIT`은 콘솔 쿼터와 동기화** — 초기 40으로 보수적으로 잡았다가 콘솔 무료 쿼터가 500임을 확인하고 500으로 정정한 이력이 있다(64c309f). 콘솔 쿼터가 바뀌면 함께 바꾼다.
- **호출은 CapacitorHttp** — 웹뷰 fetch는 CORS에 막히므로 네이티브 HTTP 경로를 유지한다.
- **키 커밋 금지** — `.env`는 gitignore 대상이고, 빌드 시에만 주입된다.
