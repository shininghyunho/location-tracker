# ADR-009: 24시간 무공백 수집 — 상시 포그라운드 + 15분 부활 잡

- **상태**: 확정 (2026-07-25, 실기기 24시간 관찰 완료 2026-07-26 — 공백 0건, 배터리 지분 3.2%)
- **결정**: 정지 중에도 포그라운드 서비스를 내리지 않고(`disableStopDetection` + `changePace(true)`), 그래도 죽는 경우를 WorkManager 15분 주기 부활 잡이 되살린다. 알림은 채널을 IMPORTANCE_MIN으로 강제해 무음·상태바 숨김.
- **대가**: 알림함 최하단에 상시 알림 1개 상존(FGS 특성상 완전 제거는 OS 정책상 불가). 정지 중에도 1분당 1픽스 GPS 소모 — 24시간 관찰에서 3.2%로 수용.

## 배경

정지 상태에서 플러그인이 포그라운드 서비스를 내려놓으면 프로세스가 캐시 상태로 밀리고, LMK·제조사 절전이 프로세스를 죽인다. 죽은 뒤엔 되살릴 주체가 없어(heartbeat는 프로세스 내부, 모션 트리거는 이동 시에만) 정지 중 몇 시간씩 수집 공백이 발생했다(대표 사례 7/20 12:16~20:14). 배터리 최적화 예외·standby EXEMPTED로는 막지 못함을 확인했다.

상세 설계·검증 절차는 [24시간 무공백 수집 설계 문서](../superpowers/specs/2026-07-25-24h-collection-design.md) 참조.

## 검토한 대안

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **C. 상시 FGS + 부활 잡 (채택)** | 킬 자체를 구조적으로 차단 + 잔여 킬(강제종료·재부팅 직후·제조사 절전)도 15분 내 복구 | 상시 알림, 정지 중 GPS 소모 | 요구(공백 ≤15분)를 유일하게 전부 충족 |
| A. 부활 잡만 | 변경 최소 | 킬 원인은 방치 — 매번 최대 15분 공백이 반복 발생 | 공백 빈도가 그대로 |
| B. 상시 FGS만 | 킬 대부분 차단 | 강제종료·재부팅 직후엔 복구 주체가 없음 | 백스톱 부재 |

## 구현에서 얻은 비자명한 사실

- `disableStopDetection: true`만으론 FGS가 안 뜬다 — `changePace(true)`로 moving 상태를 강제해야 한다.
- 플러그인의 `notification.priority` 설정은 이미 만들어진 알림 채널에 안 먹는다 — 네이티브에서 채널 자체를 IMPORTANCE_MIN으로 강제 하향했다.
- 삼성 "절대 잠자지 않는 앱" 등록은 adb로 불가, 수동 1회 필요(절차는 README).

## 후퇴선

배터리가 체감되게 늘면 1차로 수집 간격 60초→120초 완화, 그래도 과하면 상시 FGS를 롤백하고 부활 잡만 유지(공백 ≤15분은 A만으로도 충족).
