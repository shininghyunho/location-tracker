# ADR-011: 기기 로컬 소량 상태는 SQLite 대신 localStorage

- **상태**: 확정 (2026-07-26)
- **결정**: 위치 데이터(points·stays)는 SQLite에, 그 외 "잃어도 무해하고 백업할 필요 없는 기기 로컬 소량 상태"는 localStorage에 둔다. 현행 4건 — 검색 기록, 카카오 쿼터, 테마 설정, 마지막 백업 시각.
- **대가**: localStorage 항목은 JSON 백업 범위 밖 — 기기 교체·웹뷰 데이터 삭제 시 유실된다(전부 재생성 가능이라 수용). 스키마·마이그레이션이 없어 키 이름과 파싱 방어를 각 모듈이 직접 책임진다.

## 배경

검색 기록·쿼터·테마 같은 상태가 생길 때마다 "SQLite 테이블을 팔까, localStorage에 둘까"를 반복 판단하고 있었다. 같은 판단이 4곳에서 반복됐으니 경계 규칙으로 승격한다.

## 경계 기준

새 상태를 추가할 때 아래 3개를 모두 만족하면 localStorage, 하나라도 어기면 SQLite.

1. **유실 무해** — 사라져도 재생성되거나 기본값으로 충분하다.
2. **백업 불필요** — 기기 교체 시 가져갈 가치가 없다(백업 JSON은 DB만 담는다).
3. **소량·단건** — 쿼리·조인·증분 동기화가 필요 없다.

## 검토한 대안

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **localStorage (채택)** | 코드 3줄, 동기 API, web/네이티브 동일 동작 | 백업 밖, 스키마 없음 | 기준 충족 상태엔 이 단순함이 정답 |
| 전부 SQLite | 단일 저장소, 백업에 자동 포함 | 테이블·마이그레이션·비동기 오버헤드가 소량 상태엔 과함 | 과설계 |
| Capacitor Preferences | 네이티브 저장이라 웹뷰 데이터 삭제에도 생존 | web 개발 루프에서 별도 처리, 이득이 "유실 무해" 전제에선 없음 | 이득 없는 의존 추가 |
